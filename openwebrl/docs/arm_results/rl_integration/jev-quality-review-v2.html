Compare the methods


Jev and GPT-4.1 are independent comparators, not ground truth. Structural checks only validate fields. Website availability is untested.


Exactly what happens before actor pass@5


  1. Structural checks in code: task ID, nonempty instruction, valid start URL, and metadata provenance. Handle exact arithmetic and dates in code when needed.
    2. 

  2. Instruction triage: check specified target, one-episode feasibility, finite completion, contradictions, and explicit missing inputs. Return clear/problem/uncertain per dimension. A missing private prerequisite differs from a website that happens to require login today.
    3. 

  3. Human adjudication: retain legitimate broad tasks and difficult tasks. Hold ambiguous cases. Keep source-rubric redundancy/alignment advisory. Do not use a fixed confidence cutoff as an automatic rejection rule.
    4. 

  4. Browser evidence, proposed: load the actual start URL in the training browser; save screenshot, final URL, DOM/text and navigation diagnostics. A page must contain usable site content, not merely return HTTP 200. Separate parked/dead pages, CAPTCHA, authentication, transient errors and missing targets. Retry a transient failure once in a fresh session; unresolved cases stay quarantined. A working homepage does not prove the target exists or the task is solvable.
    5. 

  5. Actor difficulty, later: only valid complete actor attempts count toward 0/5. Website failures are not actor failures. No browser probes or actor attempts are included in this review.


The browser retry/session limits are a proposed protocol, not a launched or validated implementation.
