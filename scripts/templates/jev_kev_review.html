Jev & Kev in the same browser harness

Three decision models. The same ten Online-Mind2Web tasks. Fresh browser sessions for every model.

What ran

The DOM browser agent comes from Jev Ultrafast. Kev replaces its decision endpoint. OpenWebRL supplies the benchmark runner, remote browser adapter, budgets, saved artifacts, and terminal judge.

The loop repeats steps 2–5. A TYPE_TEXT choice calls GPT-4.1-mini to supply the string; Jev/Kev choose the operation and target. Screenshots are saved for review and judging, but the decision models receive DOM text.

Protocol and interpretation

“Valid” means usable saved evidence and a parseable judge verdict. It does not mean the website was accessible. Website blocks remain task failures. These are ten-task smoke tests, not full-300 benchmark estimates.

Both Kev cohorts used an explicit 4,096-token judge response cap. The earlier Jev pilot omitted the explicit cap; its longest actual judge completion was 681 tokens. AgentTrek is a lenient terminal-success protocol, so a success is a judge verdict rather than an independently verified completion of every requirement.

Debug before scaling. The upstream DOM reader can offer controls covered by overlays; its executor checks the center point and rejects those controls. This mismatch has a local regression fixture and an opt-in fix. The results below all use the original harness. Historical logs do not preserve the exact reason for every rejected decision, so the timeline labels those cases “not executed,” without assigning an unverified cause. One Kev 27B episode ended with a runtime error while attempting a dropdown selection.
